# ADR 0005: Multilingual Language Identification (LID) Strategy and Empirical Confidence Gating

- **Status**: Accepted (Implemented in Phase 2)
- **Date**: 2026-11-08
- **Scope**: Inbound text language identification across English, Hausa, Yoruba, Igbo, Nigerian Pidgin (`pcm`), and code-switched electoral messages.

---

## 1. Context and Problem Statement

The AI4Elections Hackathon (Track 3: Inclusive and Multilingual Civic Tech) requires accessible civic engagement for Nigerian voters communicating in English, Hausa, Yoruba, Igbo, and Nigerian Pidgin.

However, standard language identification (LID) tools exhibit severe, published failure modes in the Nigerian linguistic ecosystem:
1. **Pidgin Degradation**: Published benchmarks demonstrate that pure text LID tools break completely on Nigerian Pidgin (e.g. AfroLID scored only 2 out of 28 correct on real-world Pidgin messages).
2. **Code-Switching Breakdown**: Real-world civic discourse heavily mixes English with indigenous or Pidgin markers (e.g. GlotLID achieved only 21.6% accuracy on code-switched Yoruba posts).
3. **Severe Downstream Harm**: A false-positive language classification (e.g., misclassifying a Pidgin message as pure Hausa or Igbo) silently routes the query to an incorrect machine-translation engine, producing corrupted or hallucinated legal interpretations of the Electoral Act 2026.

---

## 2. Decision and Architecture

We implement **`EnsembleLID`** in [`src/lid/ensemble_lid.py`](file:///C:/Users/NDIEZE/Desktop/INEC%20Hackathon/src/lid/ensemble_lid.py) with the following civic safety rules:

### 2.1 Multi-Signal Token & Orthography Ensemble
- Evaluates token-level lexical overlap with specialized African indigenous marker lexicons (Hausa, Yoruba, Igbo), Nigerian Pidgin marker lexicons, and English indicators.
- Analyzes script-specific orthographic diacritics (Hausa hooked letters `ɗ, ɓ, ƙ`; Yoruba tonal diacritics `ẹ, ọ, ṣ`; Igbo underdots `ị, ọ, ụ, ṅ`).
- Explicitly detects code-switching when significant proportions of English and non-English markers coexist in the same message.

### 2.2 Empirical Threshold Calibration (No Arbitrary Guessing)
- Evaluated on a committed 30-sample frozen validation benchmark ([`tests/data/lid_validation_bench.json`](file:///C:/Users/NDIEZE/Desktop/INEC%20Hackathon/tests/data/lid_validation_bench.json)), balanced across all 5 languages and code-switched samples.
- **Measured Sweep Result**:
  - At an arbitrary threshold $\tau = 0.85$, accuracy degraded to **53.3%** due to excessive false disambiguation on legitimate Hausa and Yoruba messages.
  - The optimal empirical threshold is **$\tau_{\text{LID}} = 0.75$**, achieving **76.7% effective accuracy**.

### 2.3 Mandatory Human-in-the-Loop Disambiguation Policy
- **Civic Safety Mandate**: The system **never guesses silently** when uncertainty is present.
- If confidence score $< 0.75$, if code-switching is detected, or if Nigerian Pidgin is detected:
  The API returns `status = "NEEDS_LANGUAGE_CONFIRMATION"` with the interactive prompt:
  ```
  Please confirm your language / Jọwọ yan ede rẹ / Biko họrọ asụsụ gị / Da fatan za a zaɓi harshenka:
  1. English
  2. Hausa (Harshen Hausa)
  3. Yoruba (Èdè Yorùbá)
  4. Igbo (Asụsụ Igbo)
  5. Nigerian Pidgin (Naijá)
  ```
- In the Web UI, 1-click confirmation buttons appear immediately. In WhatsApp, the user replies with a single digit (`1` to `5`).

## 4. Consequences and Compliance

1. **Compliance with Hackathon Rules**: Keeps humans firmly in the loop for low-resource languages and dialectal variations.
2. **Deterministic Fallback**: Nigerian Pidgin operates as an experimental English-lexified pass-through (`EXPERIMENTAL_PIDGIN_PASSTHROUGH`), preventing unverified machine translation corruption.
3. **Traceability**: All API outputs include `LID_AUTO_DETECTED_<LANG>` or `NEEDS_LANGUAGE_CONFIRMATION` in their confidence flags.
